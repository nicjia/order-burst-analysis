# Results Provenance Ledger

Every quantitative result in `paper.tex` traced to the code that produced it, the SGE job that
ran it, and the stored panel it was aggregated from — so any number can be independently
recomputed without trusting this repository's prose.

**Data lives on Hoffman2** at `/u/scratch/n/nicjia/order-burst-analysis` (`ssh hoff`).
**Code lives here**, under git. The two are verified byte-identical by checksum below.

---

## 1. How to verify any number yourself

Each extraction wrote one CSV per ticker to `results/<group>/out/<TICKER>.csv`, concatenated
into `results/<group>/all.csv`. The aggregators in `src_py/agg_*.py` turn those panels into
the published figures. To re-derive a table from scratch:

```bash
ssh hoff
cd /u/scratch/n/nicjia/order-burst-analysis
. /u/local/Modules/default/init/bash && module load gcc/11.3.0 python/3.9.6
python3 src_py/agg_final.py        # or agg_tickplacebo.py / agg_sw3.py
```

Nothing is cached: the aggregators read `results/<group>/out/*.csv` directly. To go further
back, the per-ticker CSVs can themselves be regenerated by re-running the extractor on the
raw LOBSTER message files (`hoffman2/<driver>.sh` submits the array).

**Inference convention, applied uniformly:** the day is the unit. Markouts are equal-weighted
within name-day, averaged across the cross-section, and *t*-statistics are Newey–West with 10
lags on the daily-mean series. Name-days with |markout| > 1,000 bps at any horizon are dropped.

## 5. Known gaps in this ledger

Stated because a provenance document that hides its own holes is worthless.

- **Cluster version control starts at commit `bc73ebd`** (initialised 2026-08-13; the previous
  `.git` was an empty shell with no HEAD or refs and was not recoverable). Everything at or
  after array 14314701 is version-pinned there. **Everything before it is not**: for those
  runs, script versions are tied to results only by the checksums in §4, taken after the fact,
  so a script edited between its run and that snapshot would match the *current* file rather
  than the one that ran. The per-ticker CSVs carry no embedded version stamp.
- **Scratch purged part of `src_py/` on 2026-08-13**, after the §4 checksums were taken;
  `burst_alt.py` among others was deleted mid-session and restored from the local working copy
  (the cluster git repo at `bc73ebd` also held it). Checksums in §4 were re-verified against
  the restored copy. This is the concrete hazard the ledger's version-control gap describes:
  `/u/scratch` is not durable storage, and only the git repo and the local clone are.
- **SGE logs were not retained for `hid_depl`, `hid_hb2`, `hid_mech`, `hid_pre`.** Their data
  is intact; their scheduler receipts are not.
- **`results/research/` is empty on the cluster.** `hidden_xsec_daily.csv`, which the multi-day
  test consumes, exists only in the local working copy and is not committed (223 MB of
  `measurements/data/` is gitignored). This is the weakest link in the chain: that one input
  is single-copy.
- **`hid_tp_v1`** (array 14225689) is a superseded run — it read the BBO *at* the print rather
  than 1 ms before, making "outside the quote" endogenous. Retained for audit; **do not cite**.
  The corrected run is 14227671.
- **Raw LOBSTER message files are not stored.** Each ticker-day is streamed, reconstructed, and
  deleted to stay under scratch quota. Re-running an extractor re-downloads from
  `lobster2.math.ucla.edu`, so exact reproduction depends on that archive remaining unchanged.
- **Roughly 40% of ticker-days are absent** from the staged archive or fail reconstruction. The
  per-test name-day counts in §2 differ for this reason plus each estimator's own filter; no
  name-day is ever excluded on the basis of its outcome.
